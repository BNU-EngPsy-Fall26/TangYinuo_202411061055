# 深海声呐 · 信号检测论实验室

一个用于学习**信号检测论（Signal Detection Theory, SDT）**的交互式实验网站。
你在其中扮演远洋搜索船的声呐操作员，在充满海洋噪声的瀑布图上判断"到底有没有目标回波"；
一局结束后，网站自动算出混淆矩阵、d′、c、β、A′、ROC 等全套 SDT 指标，
并配有一个可以拖着玩的**概念实验室**，把 d′ 和 c 这两个最容易混淆的概念变成看得见的东西。

* 技术栈：**HTML + CSS + 原生 JavaScript（Canvas 2D）**
* 外部依赖：**零**。没有框架、没有构建步骤、没有 CDN 字体或图表库
* 运行方式：**双击 `index.html`** 即可

## 一、怎么运行

### 方式 1：直接双击（推荐，也是评分场景）

用文件管理器进入本目录，**双击 `index.html`**，浏览器就会打开。
不需要联网，不需要安装任何东西。

### 方式 2：起一个本地静态服务器（可选）

如果你的浏览器对 `file://` 下的 `localStorage` 做了限制（历史对比只存在内存里，不影响主流程），
可以起一个静态服务器：

```bash
# Python 3
python -m http.server 8000

# 或者 Node.js（npx 需要联网）
npx serve .
```

然后访问 <http://localhost:8000>。

> 说明：网站用的是普通 `<script>` 标签而不是 ES Module，就是为了保证在 `file://` 协议下
> 也能正常加载（ES Module 会被浏览器的同源策略拦住）。

### 跑一遍自测（可选）

项目自带一套零依赖的数学单元测试，用来验证 SDT 计算是否正确：

```bash
node tests/sdt.test.js
```

需要 Node.js 18+，不需要 `npm install` 任何东西。正常输出：

```
────────────────────────────────────────────────────
全部 73 项断言通过 ✅
```

## 二、场景设定：信号、噪音与四种后果

这是 SDT 实验的第一个前提：**必须把"信号"和"噪音"操作化地定义清楚**。

| | 定义 | 在这一帧瀑布图上的样子 |
|---|---|---|
| **信号 S** | 目标回波 —— 水下目标（失事潜航器 / 声学信标）的**窄带线谱** | 一条沿时间方向**连续延伸**的亮线，频率位置固定、强度稳定 |
| **噪音 N** | 海洋环境噪声 —— 海况、船运、降水、生物活动 | **随机散斑**，偶发短促的**宽频爆发**（虾群、鲸歌），不会连成一条线 |

**先验概率 P(S)**：每一局中"有目标"试次所占的比例，可在 10%–90% 之间调节。
它不改变你的辨别力，但会显著改变**划算的判定标准**。

**四种结果在本场景中的实际含义**（不是抽象的"对/错"，而是有代价的后果）：

| | 真实状态 | 你的回答 | 在本场景中的后果 |
|---|---|---|---|
| **击中 H** | 有目标 | 报「有」 | 搜索队第一时间出动，成功捕获 → 任务推进 |
| **漏报 M** | 有目标 | 报「无」 | 目标就在那里却被放过 → **错过最佳搜索窗口，代价最高** |
| **误报 FA** | 无目标 | 报「有」 | 搜索队扑空，消耗燃油与航时 → 资源浪费，但不会错过目标 |
| **正确排除 CR** | 无目标 | 报「无」 | 准确判断为噪声 → 效率最优 |

注意 M 与 FA 都是错误，但本场景**默认给漏报分配了远高于误报的代价**
（支付矩阵：击中 +10、正确排除 +2、误报 −4、漏报 −20）。
这个不对称正是"判定标准 c 需要权衡"的来源，也是结果页会替你算最优标准 c\* 的依据。

## 三、界面导航

顶部四个步骤，依次是：

### 1. 任务简报
场景介绍、信号/噪音定义、四种结果的后果、参数设置与操作说明。

### 2. 检测任务
每个试次：**准备（0.7 s）→ 瀑布图扫描（刺激限时）→ 作答窗口**。
扫描进行中不能作答；扫描结束的那一刻刺激冻结并开放作答，反应时（RT）从这一刻起算。
键盘 `F` = 有目标，`J` = 无目标（也可以用 `←` / `→` 或 `1` / `2`）。

### 3. 结果分析
KPI 卡片、混淆矩阵、文字解读、准确率悖论对照、双分布图、ROC 曲线、多局对比表、
逐试次明细表，以及**逐试次数据导出为 CSV**。

### 4. 概念实验室
可交互的 SDT 模型：拖动 d′、c、先验概率滑块，实时看到两个分布、
阴影面积、ROC / z-ROC、最优判据 c\* 如何变化。

## 四、可调参数

| 参数 | 范围 | 作用 |
|---|---|---|
| **先验概率 P(S)** | 10% – 90% | 有目标试次的比例。只影响划算的标准，不影响辨别力 |
| **难度 d′** | 0.2 – 4.0 | 信号强度（线谱相对噪声的振幅），控制两个分布的重叠程度 |
| **每局试次数** | 20 – 80 | 试次越多统计越稳（作业要求 ≥ 20） |
| **单次观察时长** | 1.0 – 6.0 s | 即"刺激限时"，瀑布图扫描的时长 |
| **逐次反馈** | 开 / 关 | 每答完立刻告知对错。会引导你不断调整标准，**正式实验建议关闭** |

另有 5 个一键预设：标准任务、低先验（目标罕见）、高先验（目标频繁）、
装备升级（高灵敏度）、恶劣海况（高噪声）。

## 五、结果指标与计算公式

所有指标由 `js/sdt.js` 按**等方差正态模型**计算（Macmillan & Creelman, 2005）。

设混淆矩阵计数为 H、M、FA、CR：

```
P(H)  = H / (H + M)              P(FA) = FA / (FA + CR)
zH    = Φ⁻¹[P(H)]                zF    = Φ⁻¹[P(FA)]

d′    = zH − zF                  辨别力：两个分布均值之差（以标准差为单位）
c     = −(zH + zF) / 2           判定标准：0 = 中性，> 0 保守，< 0 宽松
β     = exp(d′ · c)              似然比判据，等价于 exp[(zF² − zH²) / 2]
xc    = c + d′ / 2               判定标准在证据轴上的位置
                                  （噪音分布 N(0,1)、信号分布 N(d′,1)）

准确率 = (H + CR) / N
AUC    = Φ(d′ / √2)              等方差假设下的理论曲线下面积
```

**非参数备选指标**（不依赖正态假设）：

```
A′ = 0.5 + (P(H)−P(FA))(1 + P(H)−P(FA)) / [4·P(H)·(1−P(FA))]    当 P(H) ≥ P(FA)
A′ = 0.5 − (P(FA)−P(H))(1 + P(FA)−P(H)) / [4·P(FA)·(1−P(H))]    当 P(H) <  P(FA)
```
（Grier, 1971）

**对数线性校正**：当 P(H) = 1 或 P(FA) = 0 时，z 分数为无穷大。
此时按 Hautus (1995) 的做法，给混淆矩阵四格各加 0.5 后再计算，
结果页会明确标注"已做对数线性校正"。没有这一步，一个完美被试的 d′ 就是无穷大，无法比较。

**最优判定标准**（先验概率 + 支付矩阵）：

```
β* = [P(N) / P(S)] × [(V_CR − V_FA) / (V_H − V_M)]
c* = ln(β*) / d′
```

代入本场景默认支付矩阵（V_H=10, V_CR=2, V_FA=−4, V_M=−20）可得：
`gain = 2 − (−4) = 6`，`loss = 10 − (−20) = 30`，所以 `β* = [P(N)/P(S)] × 0.2`。
先验 50% 时 β\* = 0.2 → c\* ≈ −1.07（**偏宽松**，因为漏报代价是误报的 5 倍）；
若目标变得罕见（P(S) = 20%），β\* 升到 0.8 → c\* ≈ −0.15（**明显更保守**）。

**准确率悖论**：若本局先验 P(S) = 80%，那么**完全不看屏幕、一律回答「有目标」**也能拿到 80% 的准确率。
结果页会把这个"偷懒基线"和你的实际准确率并排画出，说明为什么准确率本身
**无法区分"看先验猜得准"和"真的看得清"** —— 这正是必须看 d′ 的原因。

## 七、实现要点与设计决策

### 1. 为什么选声呐，而不是雷达？

课堂范例和大多数教材用的是雷达。声呐与雷达在 SDT 上是同一类问题，
但瀑布图（频率 × 时间 × 能量的时频图）有一个雷达光点没有的好处：
**信号与噪音的差别可以被"看见"** —— 信号是一条沿时间连贯的线，噪音是随机散斑。
这让"什么是信号、什么是噪音"这件事不需要靠约定，而是直接被感知到，
更贴近 SDT 的本意（信号不是一个东西，而是同一个观察量在两种来源下的分布）。

### 2. 刺激是怎么生成的（`js/sonar.js`）

每帧瀑布图是一个 32（时间）× 64（频率）的矩阵：

* **背景噪声**：每个时频格的能量服从**指数分布**（这是声呐功率的经典模型），
  随机散斑，偶尔出现长尾亮点 —— 这些偶然连成一条线的散斑正是**误报**的来源；
* **偶发宽频爆发**：约 22% 的试次会出现 1–2 处短促的宽频能量（虾群、鲸歌、过船）。
  它在**信号试次和噪音试次中都会出现**，因此只是额外噪声源，不会泄露答案；
* **目标回波**：一条占据随机频率位置、沿时间延伸约 55%–75% 的窄带线谱
  （带 1–2 处断点、相邻频格有频谱泄漏），振幅由**设计 d′** 决定。

**难度 d′ 的标定**：线谱振幅与设计 d′ 之间用 `amplitudeForDprime()` 线性映射
（`0.085 + 0.115 × d′`）。这个系数是经验标定的，可以用"频带模板匹配"的理想观察者模型检验：

| 设计 d′ | 0.6 | 1.0 | 1.5 | 2.2 | 3.0 |
|---|---|---|---|---|---|
| 理想观察者可达 d′ | 1.00 | 1.57 | 2.37 | 3.51 | 4.68 |

人眼观察者通常只能达到理想值的 40%–70%，因此五个难度档预计分别落在
d′ ≈ 0.4–0.7 / 0.6–1.1 / 1.0–1.7 / 1.4–2.5 / 1.9–3.3，**两端都不退化**。
想调难度曲线，只需要改 `sonar.js` 里的这一个函数。

结果页会同时展示**设计 d′**（你设定的难度）与**实测 d′**（你真正做到的），
两者对照本身就是 SDT 的一个知识点：物理刺激的信噪比 ≠ 观察者的辨别力。

### 3. 为什么不用 ECharts / Chart.js？

因为本作业的前置条件是"助教 clone 后能**直接在浏览器打开运行**"。
引用 CDN 意味着离线打开时图表全空，用 `npm install` 又要求助教先装依赖。
所以所有图形（双正态分布、ROC、条形图、瀑布图）都是用 **Canvas 2D 手绘**的，
换来的是零依赖、零构建、双击即用。

### 4. 刺激限时的处理

扫描阶段时长固定（即"刺激限时"），扫描结束后画面**冻结**，此时才开放作答。
这样每个试次的刺激呈现时长完全一致（不会因为被试手快就少看一会儿），
RT 也从一个统一起点（作答窗口打开）开始计算。作答阶段不设倒计时，
避免"超时算哪种回答"这个会污染 SDT 统计的麻烦。

### 5. 试次序列

每局的"有目标 / 无目标"数量**严格按先验 P(S) 配比**（`Math.round(n × P(S))`）后随机打乱，
保证实际呈现的先验与设定值一致 —— 因为先验会直接影响被试的判定标准，
如果实际比例漂移，c 的解读就失去基准。

### 6. 关于分数与作答偏好

每一局的成绩都会被存进"多局对比"表（同时写入 `localStorage`，`file://` 下不可用时
自动退化为内存存储），可以横向比较不同先验、不同难度下的 d′、c、β、准确率。
逐试次数据可以一键导出 CSV（含 BOM，Excel 直接打开不乱码），方便课后自己做进一步统计。

## 九、已知限制与可拓展方向

* **难度是"物理信噪比"，不是"绝对 d′"**：设置里的 d′ 控制的是刺激的信噪比，
  你实际达成的 d′ 会受观察策略与内部噪声影响而偏低，两者在结果页并列展示。
* **等方差假设**：ROC 与 AUC 基于等方差正态模型。概念实验室提供了 z-ROC 视图，
  如果你在 z-ROC 上看到斜率明显偏离 1，就说明等方差假设不成立 —— 这本身是个可以讨论的点。
* **单场景**：本作业要求"选择一个场景"，因此只做了声呐一个场景，但把它做透了。
  若要扩展，`js/sonar.js` 的 `generateTrial()` 是唯一的场景相关处，
  换成 X 光片、安检图或质检图只需要替换这一个模块。
* **未做**：教师后台、账号系统、班级数据汇总（作业未要求，且与"纯前端双击可跑"冲突）。
